# CampusOS Phase 5 Synthetic Login Accounts

These accounts are generated by `npm run db:seed-synthetic:reset` for the fictional **Nexus Institute of Technology** tenant (`NITX`).

All names, marks, payments, applications and campus records are synthetic. Do not reuse the shared password in a real institution.

## Dataset contents

The seed removes the previous `CDU` demo tenant and rebuilds a deterministic-style synthetic operating environment containing:

- 100 student profiles
- 80 guardian profiles
- 20 faculty profiles
- 17 primary role accounts
- 30 courses and 30 course offerings
- 500 enrolments
- Attendance, assignments, submissions, examinations and results
- 100 invoices with paid, partial, pending, failed and refunded transaction scenarios
- 3 hostels, 60 rooms and 72 allocations
- 12 transport routes
- 80 library items and 180 circulation records
- 20 placement companies and 160 applications
- Notices, tickets, notifications and user-scoped audit activity

## Commands

```bash
npm run db:generate
npm run db:seed-synthetic:reset
npm run db:verify-synthetic
```

Production or Vercel seeding is opt-in:

```text
CAMPUSOS_AUTO_SEED_SYNTHETIC=true
CAMPUSOS_SYNTHETIC_ACCESS=true
```

`CAMPUSOS_AUTO_SEED_SYNTHETIC=true` rebuilds the synthetic tenant during production database preparation. It must never be enabled for a real institution database.
