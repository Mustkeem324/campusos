## 5. Root cause of Vercel build failure

**Dependency architecture is split across two package.json files with no workspace mechanism.**

- Runtime deps actually imported by the app: `bcryptjs` (lib/auth.ts), `jsonwebtoken` (lib/auth.ts), `nodemailer` (lib/email-service.ts). Also declared-but-unused: `jose`, `js-cookie`.
- These are declared ONLY in `apps/web/package.json` and were installed only in a stray gitignored `apps/web/node_modules` (490MB, next@14.2.15) — never in root `package.json` or `package-lock.json`.
- Vercel runs `npm ci` at the repo root (installing root deps only) then `npm run build` → `next build apps/web` cannot resolve `jsonwebtoken`/`bcryptjs`/`nodemailer` → **exit code 1**.
- The stray `apps/web/node_modules` (next@14.2.15 vs root next@14.2.35) ALSO caused a local-only `TypeError: Cannot read properties of null (reading 'useContext')` during prerendering — a duplicate-install artifact that does not exist on Vercel's clean install.
